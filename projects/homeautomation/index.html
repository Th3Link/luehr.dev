Project case study / Homeautomation

Home automation from circuit board to integration

An open home automation system with custom hardware, Rust firmware and a gateway between CAN and MQTT.

The problem

Relays, roller shutters, lights, buttons and sensors need to work together. That takes more than firmware on one board: it needs a shared protocol, a gateway and integration with home automation software. The system also needs to remain understandable and modifiable after installation.

My contribution

In this personal project I connect hardware, firmware and system integration, and operate the home automation system myself. The repository contains KiCad projects, 3D-printable enclosures, protocol documentation and software. Hardware and software can be considered together.

The architecture decision

Components communicate over CAN. An ESP32 gateway bridges CAN and MQTT using wired Ethernet. Rust firmware runs without the standard library, using Embassy. Hardware-independent core crates are separate from the ESP32 bindings, allowing logic to be tested on a development machine.

Testing and updates

The repository documents OTA updates for the gateway and CAN nodes, and a QEMU simulation with virtual CAN buses. CI covers formatting, Clippy, tests with coverage and dependency checks. The earlier C++/ESP-IDF implementation remains available as a reference.

Status and limits

This is openly documented, experimental hardware and firmware, rather than a finished, certified installation product. The README highlights the expertise required when working with mains voltage; documentation for some boards is still in progress.

How this connects to team development

This project shows why firmware, interfaces, testing and update capability belong together. The no_std training is relevant for microcontroller teams; system integration connects that work to Linux applications and services.
