IPv6 Router Advertisements mit Rust verarbeiten

Eine Linux-Bibliothek, die Router Advertisements empfängt, Lebenszeiten verfolgt und vollständige Zustandsänderungen pro Netzwerkschnittstelle liefert.

Projektstand geprüft am 15. November 2026

Auf einen Blick

Meine Rolle
Eigenes Open-Source-Projekt: Rust-Netzwerkbibliothek, Architektur und Tests.
Stack
Rust · Linux · ICMPv6 · Tokio
Stand
Öffentliche Rust-Crate für Linux; eine Bibliothek zur Verarbeitung von Netzwerkdaten, kein vollständiger Netzwerkmanager.
Repository ansehen →

Die Aufgabe

Eine eigene Netzwerkverwaltung braucht mehr als ein empfangenes Paket: Welche DNS-Server und Präfixe gelten noch? Was passiert, wenn mehrere Router Informationen liefern oder deren Lebenszeiten ablaufen? Dafür müssen Protokolldaten über Zeit zu einem konsistenten Zustand zusammengeführt werden.

Mein Beitrag

Ich entwickle diese Rust-Bibliothek als Baustein für Netzwerkmanager und Embedded-Systeme. Sie verarbeitet Router Advertisements unter Linux und stellt Änderungen als asynchronen Event-Stream bereit. Die Anwendung darüber entscheidet, was sie mit diesen Informationen macht.

Die Architekturentscheidung

Empfang, Parsing, Lebenszeiten und Aggregation sind getrennte Schichten. Änderungen liefern vollständige Zustände statt einzelner, schwer zusammenzusetzender Paketfragmente. Die Bibliothek setzt selbst keine Adressen oder Routen und startet keinen DHCPv6-Client. So bleibt die Konfigurationsentscheidung bei der Anwendung.

Was im Repository nachvollziehbar ist

Die README beschreibt DNS-Optionen (RDNSS/DNSSL), Präfixinformationen und Router-Flags sowie Ablaufereignisse. Die Teststrategie umfasst Unit-Tests, Integrationstests mit simulierten ICMPv6-Sockets und die Wiedergabe aufgezeichneter Router Advertisements. Code, Beispiele und Tests sind öffentlich einsehbar.

Der Bezug zur Teamarbeit

Hier kommen die Themen zusammen, die auch bei Linux-Diensten relevant sind: asynchrone Verarbeitung, klar abgegrenzter Zustand, explizite Zeitabhängigkeiten und Tests für Randfälle. Genau solche Entscheidungen lassen sich im Embedded-Linux-Training an eurem Kontext besprechen.
